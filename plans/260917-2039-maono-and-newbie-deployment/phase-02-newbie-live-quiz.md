## Overview

Port the ChatGPT Sites/Vinext + Cloudflare D1 app into the existing CT114 `/opt/ddv-training` pnpm monorepo as a native Next.js standalone container with persistent SQLite and server-only Trainer authentication.

Implementation uses `apps/newbie-quiz`, service/container `newbie-quiz` / `ddv-newbie-quiz`, and `/opt/ddv-training/data/newbie-quiz/newbie-quiz.sqlite`. Direct `better-sqlite3` transactions replaced the planned D1 compatibility adapter; this reduced migration surface while preserving server-authoritative scoring.

## Requirements

- Preserve all 35 questions, timing, scoring, tie-break, leaderboard, learner, and `/host` flows.
- Use CT114 host bind `10.10.10.114:8119`; container port `3119`.
- Store data in `/opt/ddv-training/data/newbie-quiz/newbie-quiz.sqlite`.
- Keep public learner PIN behavior unchanged. Treat Trainer key as a secret.
- Never include Trainer key in client code, query strings, request JSON after login, logs, Git, or image layers.
- Only the new service may restart during deployment.

## Architecture

```text
Browser ─HTTPS→ CT100 nginx (newbie.xid.my)
                  └─HTTP LAN→ CT114:8119
                                └─ container :3119
                                   ├─ Next.js learner + /host
                                   ├─ API routes
                                   └─ /data/newbie-live-quiz.sqlite (WAL)
```

Use the existing `/opt/ddv-training/apps/live-quiz/db/sqlite-d1-compat.ts` pattern so D1-style queries keep their semantics while the backing store changes to `better-sqlite3`.

## Implementation steps

1. Snapshot CT114 state without exposing `.env`:

   ```bash
   ssh -J xid-pve root@10.10.10.114 'cd /opt/ddv-training && git status --short && git rev-parse HEAD && docker compose -f deploy/compose.yml ps && ss -ltn | grep -E ":8114|:8117|:8118|:8119" || true'
   ```

   Stop if unrelated dirty changes overlap planned files or if 8119 is already listening.

2. Import only source/runtime files to `apps/newbie-live-quiz/`. Preserve the original handoff under `need_deploy/` until production acceptance. Run an explicit secret scan before transfer, require a new destination, then sync through the jump host:

   ```bash
   rg -n --hidden --glob '!package-lock.json' --glob '!public/**' 'HOST_KEY|DTRMASTER|BEGIN .*PRIVATE KEY|api[_-]?token|secret' need_deploy/quiz-challenge-online
   ssh -J xid-pve root@10.10.10.114 'test ! -e /opt/ddv-training/apps/newbie-live-quiz && install -d /opt/ddv-training/apps/newbie-live-quiz'
   rsync -a -e 'ssh -J xid-pve' \
     --exclude '.openai/' --exclude 'worker/' --exclude 'build/' \
     --exclude 'vite.config.ts' --exclude 'package-lock.json' \
     --exclude 'DTR Quiz Live - Hoc vien.html' --exclude 'DTR Quiz Live - Trainer.html' \
     --exclude '.next/' --exclude 'dist/' --exclude '.wrangler/' --exclude 'node_modules/' \
     need_deploy/quiz-challenge-online/ root@10.10.10.114:/opt/ddv-training/apps/newbie-live-quiz/
   ```

   The current hard-coded Trainer constant is a known finding to remove, not a value to migrate.

3. Convert runtime:

   - `package.json`: `next dev --port 3119`, `next build`, `next start --port 3119`, `eslint .`, and `node --test tests/*.test.mjs`.
   - Add `better-sqlite3` and its types at versions compatible with the existing monorepo.
   - Configure standalone output and native module externalization.
   - Replace `cloudflare:workers` imports with `getD1()` from `db/index.ts`.
   - Reuse the CT114 adapter semantics for `prepare().bind().run()/first()/all()` and transactional `batch()`.
   - Initialize database once per process; apply `journal_mode=WAL`, `busy_timeout=5000`, `foreign_keys=ON`.

4. Fix Trainer auth before build:

   - `HOST_KEY` exists only in server environment.
   - `/api/host-session` POST validates input using `timingSafeEqual`, then sets a hash-derived cookie with `HttpOnly; SameSite=Strict; Secure; Path=/; Max-Age=43200` under HTTPS.
   - `/api/live` returns player roster only when `isHostRequest(request)` passes.
   - Every control action (`reset`, `start`, `leaderboard`, `next`, `reveal`, `finish`) rejects unauthenticated requests with 403.
   - Host client removes constants, `hostKey` query parameters, and `hostKey` JSON fields.
   - Logout deletes the cookie for shared Trainer devices.

5. Protect state integrity:

   - Keep unique primary key `(player_id, question_index)` so duplicate submissions do not score twice.
   - Validate `playerId` exists before accepting an answer.
   - Validate selected answer is an integer within the current question option range.
   - Keep server time as the only scoring/timer authority.
   - Run correct-answer ranking and insert/update inside one SQLite transaction to avoid duplicate speed ranks under concurrent submissions. Extend the compatibility adapter to return `changes` metadata or use a dedicated transaction helper; add a concurrency test.

6. Add/update tests under `/opt/ddv-training/apps/newbie-live-quiz/tests/`:

   - SQLite initialization and persistence across process/container restart.
   - Join allowed only in lobby and with correct learner PIN.
   - One answer per player/question; invalid player/choice rejected.
   - Concurrent correct answers get unique submission ranks and one score update each.
   - Host actions return 403 without cookie and succeed with authenticated cookie.
   - Client build contains neither the Trainer secret nor the old hard-coded constant.
   - Reset clears active session data only as current product behavior specifies.

7. Add compose service:

   ```yaml
   newbie-live-quiz:
     build:
       context: ..
       dockerfile: apps/newbie-live-quiz/Dockerfile
     image: xid-ddv-newbie-live-quiz:latest
     container_name: ddv-newbie-live-quiz
     restart: unless-stopped
     environment:
       HOST_KEY: ${NEWBIE_LIVE_QUIZ_HOST_KEY:?set NEWBIE_LIVE_QUIZ_HOST_KEY in deploy/.env}
       DDV_DB_PATH: /data/newbie-live-quiz.sqlite
     volumes:
       - ${DDV_DATA_DIR:-./data}/newbie-live-quiz:/data
     ports:
       - "${DDV_BIND_ADDR:-0.0.0.0}:8119:3119"
     healthcheck:
       test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:3119/api/live').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
       interval: 30s
       timeout: 5s
       retries: 3
       start_period: 20s
   ```

8. Generate secret only on CT114 and append it without printing:

   ```bash
   ssh -J xid-pve root@10.10.10.114 'umask 077; cd /opt/ddv-training; test -f deploy/.env; grep -q "^NEWBIE_LIVE_QUIZ_HOST_KEY=" deploy/.env || printf "NEWBIE_LIVE_QUIZ_HOST_KEY=%s\n" "$(openssl rand -base64 32)" >> deploy/.env; chmod 600 deploy/.env'
   ```

   Do not run `docker compose config` without `--quiet`, because resolved output may reveal environment values.

9. Pre-deploy gates on CT114:

   ```bash
   cd /opt/ddv-training
   ```

## Risk assessment

- **Scoring race:** current D1 logic counts then inserts in separate operations. Use one SQLite transaction and test concurrent answers.
- **Secret leak:** current source embeds a Trainer constant client-side. Gate deploy on bundle scan and unauthenticated 403 checks.
- **Native module build:** use the existing Node 22 Bookworm Docker pattern with compiler packages only in build stages.
- **PII retention:** learner name/department are personal data. Add backup and retention behavior; do not log request bodies.
- **Shared monorepo:** build/restart by service name only; do not run unscoped `docker compose up -d --build`.

## Rollback

For first release, stop/remove only `ddv-newbie-live-quiz`, disable only the new nginx site, and leave `/opt/ddv-training/data/newbie-live-quiz/` intact. Revert the CT114 repository commit normally; never reset the shared repo or restart existing services.
